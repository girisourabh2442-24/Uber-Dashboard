## 1. Data Dictionary (`Uber` Table)

The dataset contains approximately **150,000 ride booking records**. Below is the schema used across Power Query, DAX, and SQL verification scripts:

| Column Name | Data Type | Description | Example Values |
| :--- | :--- | :--- | :--- |
| `Booking ID` | Text / Key | Unique identifier for each ride request | `CNR5884300` |
| `Booking Date` | Date | Date when the booking was placed | `2024-03-23` |
| `Booking Time` | Time | Timestamp of the ride request | `12:29:38` |
| `Booking Status` | Text | Final outcome of the booking | `Completed`, `Cancelled by Driver`, `Cancelled by Customer`, `No Driver Found`, `Incomplete` |
| `Customer ID` | Text | Unique identifier for the rider | `CID1982111` |
| `Vehicle Type` | Text | Requested ride category | `Auto`, `Go Mini`, `Go Sedan`, `Bike`, `Premier Sedan`, `eBike`, `Uber XL` |
| `Pickup Location` | Text | Starting point of the trip | `Palam Vihar`, `Shastri Nagar` |
| `Drop Location` | Text | Destination of the trip | `Jhilmil`, `Khandsa` |
| `Ride Distance` | Decimal | Trip distance in kilometers (`NULL` for uncompleted rides) | `12.40` |
| `Booking Value` | Currency (₹) | Fare amount generated by the booking (`NULL` for uncompleted rides) | `508.30` |
| `Payment Method` | Text | Mode of payment selected by the rider | `UPI`, `Cash`, `Uber Wallet`, `Credit Card`, `Debit Card` |
| `Driver Ratings` | Decimal | Rating given to the driver (`1.0` – `5.0`) | `4.5` |
| `Customer Rating` | Decimal | Rating given by the driver to the customer (`1.0` – `5.0`) | `4.4` |

## 2. Power Query Transformations

Before loading the CSV into the Power BI model, the following cleaning and shaping steps are applied in **Power Query**:

1. **Data Type Standardization:** Enforced `Date` on `Booking Date`, `Decimal Number` on `Booking Value`, `Ride Distance`, and ratings, and `Text` on IDs and categorical fields.
2. **Whitespace & Casing Hygiene:** Trimmed leading/trailing spaces on `Booking Status`, `Vehicle Type`, and `Payment Method` so DAX filters and `IN` lists evaluate accurately.
3. **Null Handling:** Kept `NULL` values intact for `Booking Value` and `Ride Distance` on cancelled/unfulfilled trips so `AVERAGE()` measures are not skewed downward by zeros.
4. **Date Attributes:** Extracted `Month`, `Month Name`, and `Quarter` columns (or linked to a dedicated `Date` table) to support the interactive **Month / Quarter** trend toggle.

## 3. Data Model & Star Schema Notes

To keep filtering fast and calculations unambiguous across all three report pages, the model follows a clean star-schema design:

```text
                  ┌──────────────────────┐
                  │      Dim_Date        │
                  │  - Date (PK)         │
                  │  - Year / Quarter    │
                  │  - Month / Week      │
                  └──────────┬───────────┘
                             │ 1
                             │
                             │ *
┌──────────────────────┐     │     ┌──────────────────────┐
│    Dim_Vehicle       │1   *│*   1│    Dim_Payment       │
│  - Vehicle Type (PK) ├─────┼─────┤  - Payment Method(PK)│
└──────────────────────┘     │     └──────────────────────┘
                             │
                  ┌──────────┴───────────┐
                  │      Fact_Uber       │
                  │  - Booking ID (PK)   │
                  │  - Customer ID       │
                  │  - Booking Status    │
                  │  - Booking Value     │
                  │  - Ride Distance     │
                  │  - Ratings           │
                  └──────────────────────┘
```

* **Relationship Cardinality:** One-to-many (`1:*`) single-direction filtering from dimension attributes (`Date`, `Vehicle Type`, `Payment Method`) down to the `Fact_Uber` table.
* **Measures Table:** All DAX calculations are organized in a dedicated `_Measures` display folder/table to keep the Fields pane clean.

## 4. DAX Measures Reference

### Volume & Customer Metrics

```dax
Booking Count = 
DISTINCTCOUNT(Uber[Booking ID])

Total Customer = 
DISTINCTCOUNT(Uber[Customer ID])

Completed Bookings = 
CALCULATE(
    [Booking Count],
    Uber[Booking Status] = "Completed"
)

Lost Bookings = 
CALCULATE(
    [Booking Count],
    Uber[Booking Status] <> "Completed"
)
```

### Conversion & Cancellation Rates

```dax
Successful Booking Rate = 
DIVIDE(
    CALCULATE(
        COUNTROWS(Uber),
        Uber[Booking Status] = "Completed"
    ),
    COUNTROWS(Uber),
    0
)

Cancellation Rate (%) = 
DIVIDE(
    CALCULATE(
        COUNTROWS(Uber),
        Uber[Booking Status] IN {
            "Cancelled by Driver",
            "Cancelled by Customer"
        }
    ),
    COUNTROWS(Uber),
    0
)
```

### Revenue & Distance Metrics

```dax
Booking_Value = 
SUM(Uber[Booking Value])

Average Booking Value = 
AVERAGE(Uber[Booking Value])

Total Distance = 
SUM(Uber[Ride Distance])

Average Distance = 
AVERAGE(Uber[Ride Distance])
```

### Rating Metrics

```dax
Average Customer Rating = 
AVERAGE(Uber[Customer Rating])

Driver Rating Count = 
COUNT(Uber[Driver Ratings])
```
